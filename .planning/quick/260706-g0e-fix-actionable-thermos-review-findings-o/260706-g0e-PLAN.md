# Quick Task 260706-g0e: Fix actionable Phase 10 Thermos re-review findings

## Context

The 2026-07-06 re-run of the Phase 10 Thermos review (after the `9c62bba` OTEL
third-recurrence fix + `1c9873c` live re-confirm) found 0 critical, 12 warning,
5 info findings — 835 pytest passed. The third-recurrence OTEL fix is correct
and live-verified for the PRIMARY single-call path, but it EXPOSED two new

### Task 1 — OTEL retry/degrade accounting: distinct per-attempt paths, degrade isolation, extracted helper (WR-T11, WR-T12, WR-T13, IN-T04)

**Files:** `src/prevue/engines/cli_adapter.py`, `src/prevue/engines/flow.py`, `tests/test_copilot_adapter.py`

**Action:**

1. **WR-T13** — In `cli_adapter.py`, extract the current ~25-line inline `otel_path`
   construction block inside `review()` (the WR-01/THIRD-RECURRENCE comment
   archaeology plus `os.makedirs`/`uuid.uuid4().hex + ".jsonl"` logic, currently
   `review()`'s lines ~222-247) into a module-level helper
   `_build_copilot_otel_path(base_dir: str) -> str | None`. The helper: builds a
   FRESH per-attempt subdirectory `os.path.join(base_dir, uuid.uuid4().hex)`,
   creates it via `os.makedirs(..., exist_ok=True)` inside a
   `try: ... except OSError: return None` (moves the existing OSError-degrade
   branch INTO the helper instead of `review()`), then returns
   `os.path.join(that_subdirectory, f"{uuid.uuid4().hex}.jsonl")` — a leaf path
   that is never pre-created (preserves the third-recurrence invariant). One
   docstring on the helper states both invariants: (a) the returned leaf file
   itself must never exist on disk when the Copilot subprocess starts (the real
   1.0.67 file exporter no-ops otherwise), and (b) each attempt is nested under
   its OWN fresh subdirectory of `base_dir` — not a flat `base_dir/<uuid>.jsonl`
   sibling — specifically so a directory-level glob of `base_dir` (used only by
   the degrade fallback in `flow.py`, see point 3) can never pick up another
   call's real span file (WR-T12).

2. **WR-T11 (cli_adapter.py)** — In `review()`, call `_build_copilot_otel_path(base_otel_dir)`
   TWICE when `self._spec.usage_capture == "otel-jsonl"` and
   `COPILOT_OTEL_FILE_EXPORTER_PATH` is set: once for `otel_path` (first
   attempt), once for `retry_otel_path` (retry attempt) — two independently
   fresh paths, not one path reused for both. Replace the single
   `invoke=lambda p: self._invoke(p, env, ...)` closure currently passed to
   `flow.review_with_retry` with a small closure that tracks which attempt is
   executing (`review_with_retry` calls `invoke()` at most twice: first, then
   retry — a plain counter or a two-item list popped per call is enough) and
   builds a PER-ATTEMPT env dict, setting `COPILOT_OTEL_FILE_EXPORTER_PATH` to
   `otel_path` on the first call and `retry_otel_path` on the second, before
   delegating to `self._invoke(...)`. Pass both `otel_path=otel_path` and a new
   `retry_otel_path=retry_otel_path` kwarg into `flow.review_with_retry`. This
   is the actual behavior fix: before this change, the SAME `env` dict (and
   thus the same `COPILOT_OTEL_FILE_EXPORTER_PATH` value) was reused for the
   retry subprocess invocation, so Copilot's real file exporter — which no-ops
   when the configured path already exists — never wrote a real span for the
   retry attempt, and the retry silently degraded to a `~est` partial estimate
   every time, even when both invocations actually reached the OTEL-emitting
   `-p` code path.

3. **WR-T11 (flow.py)** — Add `retry_otel_path: str | None = None` to
   `review_with_retry`'s signature. Immediately after the existing `otel_path`
   env-var fallback block (~lines 465-467), default `retry_otel_path` to
   `otel_path` when it is still `None` — this preserves byte-identical
   behavior for every existing caller/test that only passes a single
   `otel_path` (both OTEL tests in `tests/test_engine_flow.py`, and any future
   direct caller). Change the retry invocation's `_enrich_capture(...)` call
   (~line 538, inside the `if fence_err:` retry branch) to read from
   `retry_otel_path` instead of `otel_path`. Change `_otel_accumulates`'s
   computation (~line 473) from
   `spec is not None and spec.usage_capture == "otel-jsonl"` to additionally
   require `retry_otel_path == otel_path` — i.e. only treat the retry's
   capture as "the JSONL directory already accumulated first+retry" (discard
   `first.captured`, trust `retry.captured` alone) when both attempts
   literally reused the SAME path (the legacy/test-only shared-directory model
   exercised by `test_merge_retry_tokens_otel_no_growth_falls_back_to_estimate_for_retry`
   and `test_merge_retry_tokens_otel_growth_still_sums_normally` in
   `tests/test_engine_flow.py`, both of which pass one static `otel_path` and
   no `retry_otel_path`). When cli_adapter supplies two DISTINCT paths (the
   fixed production behavior), `_otel_accumulates` is now `False`, so the
   existing `else` branch in `_merge_retry_tokens` correctly SUMS
   `first.captured` + `retry.captured` (via `_retry_token_meta`'s real-field
   summing) instead of discarding `first.captured` — discarding it would
   otherwise now silently drop the first invocation's real tokens, since
   `retry.captured` no longer contains them (it is isolated to its own file).

4. **IN-T04** — Update the two stale OTEL comments this change touches: the
   `_merge_retry_tokens` block (~lines 386-394 in `flow.py`, the exact lines
   IN-T04 cites) and `_otel_capture_grew`'s docstring (~lines 278-291), both of
   which currently assert the JSONL directory unconditionally "accumulates
   spans from ALL invocations." Rewrite both to state accumulation only holds

   fix) gives them distinct per-attempt paths, so a real retry capture
   reflects only that attempt's own spans and must be summed with
   `first.captured`, not treated as already inclusive of it.

5. **Regression tests** — in `tests/test_copilot_adapter.py`'s
   `TestOtelPerCallIsolation` class, add:
   - `test_retry_gets_distinct_otel_path_with_real_capture` (covers WR-T11 +
     IN-T05 in one test — do not duplicate): drive a full `adapter.review()`
     call through a fence-error-then-retry cycle (first mocked-subprocess

   - `test_second_calls_makedirs_oserror_degrade_ignores_sibling_calls_real_spans`
     (covers WR-T12): call `adapter.review()` once successfully with the
     mocked subprocess writing a real 5000/900-token span at its assigned
     per-call path (no retry needed — return a valid fenced stdout
     immediately); assert that first call's tokens are `estimated=False`
